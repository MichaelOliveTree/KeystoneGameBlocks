Footprint Editor

Posted on July 19, 2013 by Big Mike
Reply

I’ve added a new tool to my Keystone Game Blocks editor that enables you to visually draw the footprint of tile place-able components.   Footprints are a simple and fast way for tiled regions to track whether something already exists in a particular space.  It’s much  faster than for example, trying to do real-time 3D collision tests.  The idea is that by using tiles we’ll be able to have much denser NPC counts inside our ships compared to a game that relied solely on 3D spatial tests for managing path finding and collisions.

The above image is using a debug friendly texture (1s and 2s) to show the areas on the footprint mask that the application should consider as occupied by the chair geometry.  Thus when the chair is placed on a floor inside a ship, the highlighted areas of the footprint will transfer onto the tile masks in the ship floor preventing any other objects from being placed there as well as allowing NPCs to know how to avoid running into the chair when path finding across the floor.

I still have to fix a few minor bugs and add a few features (namely transparency so you can see occluded areas) to make it easier to use, however, being able to visually define component footprints WYSIWYG style for the numerous new components I’ll eventually be adding will save lots of time and energy compared to editing data files by hand.

Interior Work: Cell Database & Tile Masks

Posted on July 5, 2013 by Big Mike
Reply
  • Redesigned interior cell storage database layout.
  • File I/O of interior cell database rewritten accordingly.
  • Rewrote tile mask visualization using a single quad with shader and texture atlas.
  • Implemented application of component footprints to the tile mask.
  • Initial A-Star (A*) path finding work utilizing footprint data in the tile mask to evaluate obstacles.  Not quite functional yet… but soon.

That’s a rather cryptic looking image but this was an early test of the quad shader for visualizing the values of the underlying tile masks.  I’m currently using 16×16 tiles within each cell.  Each cell represents 1.5 meters x 1.5 meters and contain 256 tiles.  There are currently 48×19 cells in each quad (and this is variable and may change depending on the ship) so that results in 233472 tiles.  Using the shader with atlas texture to visualize them is very fast.  There’s some obvious edge bleeding  between the tiles visible which I haven’t fixed yet.  It’s a common issue encountered when sampling from atlas textures usually solved by adding an extra border pixel around each separate image in the texture.

About…

Posted on May 29, 2013 by Big Mike
Reply

At it’s core, the project is a starship captain simulator.  As Captain, you will decide the design of your ship, the composition and duties of your crew and the missions and adventures you undertake.  Graphics will be good but they are not the focus.  The primary focus is gameplay and depth of simulation and giving the player a sense of what it might be like to captain a starship.

Key features:

  • Procedurally generated universe.
  • Accurately scaled star, planet and moon sizes and distances between celestial bodies.
  • Gravitation and Newtonian movement for spacecraft.
  • Realistic orbits for moons, worlds and multi-star systems.
  • Quasi-hard sci-fi space battles reminiscent of naval and submarine battles.  Battles typically take place at long range and near celestial bodies.
  • Single player scripted campaign as well as a random sandbox exploration style campaigns for unlimited replayability.
  • Network multiplayer capital ship “versus” matches as well as persistant faction based campaigns (versus and co-op).
  • 100% custom ship design via a user friendly deckplan editor.
  • AI Crew Management.
  • Ship Systems management (power distribution, targeting, damage control, etc).
  • Away team missions.
  • Boarding parties.
  • and more!
